# ADR 0017 — PromoStandards supplier connections

**Status:** Accepted · **Date:** 2026-09-24 · Builds on ADR 0002 (RLS), 0003 (flags), 0008 (secrets, SSRF), 0009 (pricing), 0015 (workers)

## Context
Distributors keep their catalogs in step with suppliers by hand today (CSV and seed data). The
promotional-products industry exposes supplier data through PromoStandards: SOAP web services,
one set per supplier, authenticated with an account ID and password the supplier issues to each
distributor. The plan catalog already had an Enterprise entitlement (`promostandards_live`) with
nothing behind it.

**Not verified against a real supplier.** No PromoStandards account was available while building
this. Everything is tested against a built-in fake supplier written from the published schemas.
Real suppliers vary; the first live connection is the real test, and mapping rules will need
tuning from what it reports.

## Decisions
1. **Two services, read-only.** Product Data 2.0.0 (`getProductSellable`, `getProduct`) and
   Pricing & Configuration 1.0.0 (`getFobPoints`, `getConfigurationAndPricing`). Blank pricing
   is requested first; the Decorated configuration only when Blank lists no decoration locations.
   Inventory, Media Content and order services are out of scope.
2. **Our own strict XML reader, no dependency.** SOAP responses come from third-party servers.
   The reader refuses any DOCTYPE (so no entity expansion or external entities), decodes only the
   five predefined entities and numeric references, caps size (20 MB) and depth (64), and matches
   elements by local name because suppliers use different namespace prefixes.
3. **Supplier addresses get the webhook protections (ADR 0008).** https only, no credentials in
   the URL, no internal names or addresses, every resolved address checked at connect time,
   redirects never followed, 60 s timeout. Unlike the webhook, validation is always strict: the
   test-only switch that lets webhooks use http never applies to suppliers.
4. **Mapping is strict: report, never guess.** A product imports only if it has a render
   template (from sub-category, category, then name; the adapter accepts a per-product template
   override, but connections don't store one and the UI can't set it yet), at least one colour with a hex (supplier's, or a small
   table of common names), at least one decoration method we price on a print area that template
   has, and a readable blank price. Anything missing is listed in the sync summary in plain words.
   Ambiguous decoration names (a "Full Color Transfer" could be vinyl, DTF or a printed transfer)
   are left out rather than mispriced.
5. **Prices are exact.** Decimal strings become integer cents without floating point, half up;
   per-dozen, hundred and thousand units are converted to per-each; unknown units are skipped
   and reported. Parts usually differ by colour and size, so the part with the lowest first break
   (standard sizes) sets the price; upsize surcharges aren't modelled yet. Net (the distributor's
   cost) by default, so their markup applies on top; prospects only ever see selling prices.
6. **Storage.** `supplier_connections` (under RLS) holds the addresses, account ID, the password
   sealed with the tenant bound in (ADR 0008), currency, price type, optional FOB and product
   picks, and the last sync summary. Products gain `supplier_connection_id`,
   `supplier_product_id` and `active`; a unique index on (tenant, connection, supplier product)
   makes re-syncs update in place. Name or slug clashes with the tenant's other products get the
   supplier product id appended, deterministically. Migration `drizzle/0004` was generated by
   drizzle-kit from the schema.
7. **Hide, never delete.** Products the supplier stopped selling, or that fall outside the
   distributor's picks, are hidden: leads and proofs may reference them. Hiding only happens after
   a run that saw the whole list (not capped), and a product that errored this run is kept as it
   was. Removing a connection hides its products and deletes the sealed password.
8. **Imports check the connection under RLS.** Postgres foreign-key checks bypass RLS, so a key
   alone wouldn't stop a product being linked to another tenant's connection. The import first
   reads the connection inside the tenant's scope and refuses one it can't see.
9. **Syncs run in the background.** An owner's "Sync now" queues the connection; a worker runs it
   (inline by default, or `npm run jobs:suppliers` with `SUPPLIER_WORKER=off`), plus a daily
   refresh for connections synced before. Never-synced connections wait for the owner. The status
   column is the lock: one run per connection, and a lock older than 30 minutes (a crashed worker)
   can be taken over. A run handles at most 500 products; the rest wait for picks.
10. **Plan checked when the run starts.** Creating, editing and syncing need `promostandards_live`
    (Enterprise); a tenant that loses it gets a failed run with that reason, its products unchanged,
    and no more daily refreshes. Removing works on every plan. Owners only; every change audited.
11. **Bad credentials stop the run** at the first rejected call (PromoStandards codes 100, 104,
    105, 110), instead of repeating the same failure for every product.
12. **A fake supplier for development and tests** answers on `https://promostandards.example`
    (a reserved name that never resolves). It's on in the unit tests and the dev server, opt-in via
    `PROMOSTANDARDS_FAKE_SUPPLIER=true` elsewhere, and refused by env validation in production.

## Consequences
- Settings has a **Suppliers** section for owners. Browser suites cover connecting (including an
  insecure address refused next to its field), syncing, what was left out, imported products in
  the storefront, editing without the password, narrowing, and removing.
- `src/core/db/suppliers.test.ts` runs a full sync into Postgres; `rls.test.ts` proves isolation;
  `smoke:pg` covers the endpoints, sealed storage and the worker's failure path against the
  production build (where the fake supplier is off by design).
- Not built: template choice in the UI, inventory, media (product photos), upsize pricing,
  supplier decoration charges (distributors' own rate tables price decoration), and the
  PromoStandards company directory lookup for service addresses.
